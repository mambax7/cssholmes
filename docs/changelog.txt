<h5>3.3.0 Alpha 1 [2026-10-26]</h5>
Requires PHP 8.4+. Alpha prerelease for testing; see docs/compatibility.md for tested environments and limitations.
<hr>
- Moved the official repository to XoopsModules27x/cssholmes and updated source, help and release links.
- Added a visual theme designer with scoped selectors, colors, typography, spacing, live preview, undo/redo and explicit Save to theme publication.
- Added private per-theme override storage, export, previous-save restoration and optimistic conflict checks without rewriting theme source files.
- Added a named style-set library with preview, categories, likes and validated portable import/export; saving a set does not publish it.
- Added xStyles example inspection/editing, private published-versus-draft comparison and three-width draft previews.
- Added contrast-to-color controls and temporary selected-element highlighting.
- Preserved the editing revision across library refreshes so concurrent set updates are rejected safely.
- Kept selected palette names and swatches visible after library refreshes across Chromium versions.
- Added shared QA runner, PHP 8.4/8.5 CI, optional Qodana and release packaging without module-local development dependencies.
- Moved workbench histories to private storage with migration, locked updates and atomic writes; removed bundled development history.
- Prevented unsafe imported patches and rollback over later template edits; fixed literal CSS replacements and scan diagnostics.
- Enforced designer export permission, protected manifest edits from external symlinks, and bounded import history without deleting rollback records.
- Corrected named-color and image-dimension checks, form-label associations, missing-landmark counters, dark-mode detection and widget-root highlighting.
- Escaped inspected page text and exported changes in overlay HTML, derived diagnostic stylesheet URLs from the module script, and simplified font-family validation.
- Avoided repeated core initialization during install, made uninstall backup names unique, and removed duplicate GD status output.
- Supported trusted deployment symlinks while retaining storage-file checks; corrected legacy copy and database helper failures.
- Excluded local workbench JSON records from release archives so upgrades do not overwrite a site's saved workbench data.
- Read-only resolved token inspection and conservative rendered text contrast estimates.
- XTF data-theme mode support in draft and public CSS; content-based stylesheet ETags.
- Kept ordinary xStyles comparison frames published-only with editor assets suppressed; private draft panes accept only the matching theme.
- Added XMF 2 / XTF package contract, diagnostics and frame integration checks.
- Added an illustrated cssHolmes + xStyles tutorial, shared-tool contributor instructions and explicit compatibility documentation.
- Verified clean ZIP installation and upgrade from 3.0.0 on a disposable XOOPS 2.7.4-RC2 site: configuration, existing permissions and saved designer overrides are preserved.

Earlier unreleased development included in this release:
- added permission checks to all admin workbench pages and actions (mamba)
- added a new "cssHolmes Admin" permission for granular control over who can access the admin workbench (mamba)
- added **Diagnose (third row):**
        - `overflow` — highlight every element with overflowing content
        - `z-index` — show z-index values as colored labels on all positioned elements
        - `grid` — show CSS Grid and Flexbox containers with column/row lines
        - `proto` / `deuter` / `trita` / `achro` — simulate color blindness types
- added CSS Grid and Flexbox diagnostics to the front-end inspection overlay (mamba)
- changed install defaults: Use Overlay and Use Diagnostics now go to the Webmasters group only; earlier versions also granted them to Registered Users (mamba)
- updates do not change existing permissions: when Registered Users still hold the old overlay/diagnostics grants, the update log and the admin Index and Permissions pages show a notice so the administrator can remove them (mamba)
- fixed the "Overlay query key" setting description, which claimed the overlay was for administrators only (english, french) (mamba)
- fixed keyboard shortcuts I, M, T, P, U: they now ignore Ctrl/Cmd/Alt (Ctrl+P and Ctrl+U work again), never fire while typing, only work while the toolbar is open, and only block the key they handle (mamba)
- changed Esc to leave inspect and measure mode and close the editors; minimising the toolbar does the same, so a minimised toolbar no longer captures clicks (mamba)
- fixed the E/W counters ignoring html5 findings: every profile rule now sets a --holmes-{profile} severity marker that the counters read, instead of matching outline colours (mamba)
- fixed the html5 body attribute rules (background, *margin, bgproperties), which never matched because the overlay puts holmes-debug on <html> (mamba)
- changed the html5 profile to treat table summary as obsolete (grey) instead of requiring it (red) (mamba)
- added Smarty-aware template reading to the analyzers: Smarty comments and tags are neutralised before HTML checks, so <img src="<{$x}>" alt="..."> is no longer cut at the first }> (mamba)
- added include resolution to the analyzers: <{include file="$theme_name/tpl/x.tpl"}>, `$xoTheme->folderName`, |cat: chains and plain relative names are followed, so skip link, main, lang and module header checks see the included partials; missing theme includes are reported with file and line (mamba)
- changed accessibility element checks (img alt, empty links and buttons, form labels, tabindex) to report every occurrence with file and line, to ignore <a> without href (fragment targets) and inputs wrapped in <label>, and lowered "no h1 in the theme" to info (mamba)
- changed the workbench theme list to include every theme folder with theme.tpl or theme.html; themes without theme.json are scanned in generic mode (no manifest checks, token checks based on the theme's own custom-property prefix such as --mt-) (mamba)
- fixed $xoops_sitename and $xoops_slogan being reported as unescaped: core already escapes them (and $xoops_requesturi and $xoops_meta_*) in class/theme.php; $xoops_pagetitle is still reported, with a suggestion that does not double-encode (mamba)
- changed "theme.tpl does not print $xoops_module_header" from info to warning (mamba)
- added the command-line theme scan bin/holmes-scan.php: runs the analyzers on a theme folder without a XOOPS install, text or --format=json output, exit code 1 on errors (or --fail-on=warning) for release checks and CI (mamba)
- added scan history to the workbench (ScanStore): an explicit theme scan is stored (last 20 per theme) and compared with the previous one (mamba)
- added unit tests for Smarty stripping, include resolution, the generic-theme analyzers and the CLI exit codes, with fixture themes in tests/Unit/fixtures (mamba)
